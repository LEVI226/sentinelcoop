# Backlog MVP Topic 1

## Priorité 1 - Démo obligatoire

| Fonction | Pourquoi | Critère jury |
| --- | --- | --- |
| Création client KYC | Point d'entrée du filtrage | Pertinence |
| Contrôle CNIB | Besoin terrain explicite | Pertinence |
| Filtrage sanctions/PPE | Cœur du sujet | Pertinence |
| Matching approximatif | Homonymies et translittérations | Innovation |
| Création compte multi-caisse | Réseau CIF | Impact |
| Saisie dépôt/retrait | Opérations de caisse | Faisabilité |
| Retrait par procuration | Cas terrain différenciant | Pertinence |
| Alertes informatives/bloquantes | Demande TDR | Pertinence |
| File de revue conformité | Gouvernance humaine | GRC |
| Journal d'audit | Preuve conformité | GRC |

## Priorité 2 - Différenciation

| Fonction | Pourquoi |
| --- | --- |
| Solde global multi-comptes | Exigence TDR |
| Cumul des opérations par client | Détection de contournement |
| Paramétrage par zone | Réponse aux caisses Dori/Banfora |
| RBAC et masquage | Réponse visibilité réseau |
| Mode hors ligne avec listes locales | Contrainte hackathon |
| Import listes CSV/JSON | Mise à jour sans délai |
| Explication du score d'alerte | Réduit les faux positifs |

## Priorité 3 - Bonus

| Fonction | Pourquoi |
| --- | --- |
| Export rapport conformité | Utile pour inspection |
| Tableau indicateurs | Impact mesurable |
| Simulation réseau multi-caisses | Montre interopérabilité |
| Historique versions des listes | Renforce gouvernance |
| Workflow déclaration suspecte | Bonne maturité GRC |

## Ce qu'il ne faut pas faire en premier

- Construire un modèle IA opaque sans règles explicables.
- Dépendre d'une connexion Internet permanente.
- Utiliser un vrai fichier client.
- Faire une application trop large sans démo fluide.
- Donner à tous les rôles la visibilité complète du réseau.
